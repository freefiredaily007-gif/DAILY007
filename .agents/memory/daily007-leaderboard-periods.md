name: Daily007 leaderboard periods
description: Match-date attribution and Full Admin-approved weekly/monthly top-three rewards.
---

Leaderboard awards belong to the IST week or month containing the tournament's scheduled start time, not the later time when an administrator publishes results. At expiry, the scheduler snapshots standings and the cycle's reward configuration as `pending_approval` and does not start a successor. Only a Full Admin can approve an ended cycle; approval pays positive configured rewards for ranks 1–3, records approver/time and resulting wallet balances, and finalizes atomically. After all ended payouts for that cycle type are approved, a Full Admin must set fresh rank rewards and explicitly schedule the next cycle. It remains `pending_activation` until the next IST calendar boundary (Monday for weekly, the 1st for monthly), then activates. Tournament Admins cannot access this flow.

**Why:** Tournament results can be published after the match, so award creation time can put an earlier match into a later cycle. Payouts require explicit Full Admin review, and reward amounts for the next cycle must also be a deliberate fresh decision rather than silently carrying forward.

**How to apply:** Attribute result awards through the match's `starts_at`. Edits to an active or scheduled period apply only to that period. At expiry, snapshot standings and rewards but do not modify wallets or create a successor. Keep pending approvals visible until paid. On Full Admin approval, use stable ledger idempotency keys and one transaction for all wallet updates, balance-after ledger entries, approver metadata, and finalization; repeated approval must never pay twice. Scheduling requires the latest period to be finalized and no older payout awaiting approval; store the submitted fresh rewards with the next-boundary period, then activate it only when its IST start time arrives.
