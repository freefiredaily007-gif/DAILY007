---
name: Expo Go LogBox in Android Maestro flows
description: Diagnose lower form taps that open Expo Go warning details during Android emulator tests.
---

When a Maestro flow running through Expo Go opens a “Log N of M” warning screen after tapping a form field, the visible LogBox may be taking the touch even when Maestro's hierarchy still identifies the underlying native input. Center lower form fields and buttons in the viewport before tapping them, then inspect the captured screen if the next selector disappears.

Opening the same Expo Router fixture URL in a new Maestro flow may preserve its mounted React state. Explicitly select a reset scenario at the start of each flow instead of assuming `openLink` remounts the fixture. On Home tests, wait for the asynchronous carousel container before searching for one of its cards, and avoid scrolling away from the expected top position. After navigating back from a non-first carousel card, assert that the same card remains selected and visible; the earlier card is offscreen until swiping back. Avoid running a whole flow directory when one test requires custom system settings; run that flow only through its setup runner.

**Why:** Android CI showed the player-name field near the bottom of the viewport, followed by a full-screen Expo warning detail instead of the next form control. The accessibility hierarchy can describe an element underneath a native overlay. The Home carousel can also advance between a fixture-card lookup and tap, opening a different match; after disabling autoplay, a test still incorrectly expected an offscreen first card after returning from the second. Directory-based Maestro runs also included a 1.5× flow before its dedicated runner changed the emulator settings.

**How to apply:** In Expo Go emulator flows, reset fixture state explicitly between same-route flows, wait for async fixture data, and disable carousel autoplay in fixtures that assert a specific card. Assert the card selected before opening details after Back returns. Keep system-setting-dependent flows out of generic directory runs; invoke them through runners that apply, verify, and restore the device setting. Scroll/center form inputs before tapping—especially when warning toasts or LogBox notices are present. Treat a missing follow-up selector as a possible overlay or lifecycle issue, not automatically as a missing app field.
