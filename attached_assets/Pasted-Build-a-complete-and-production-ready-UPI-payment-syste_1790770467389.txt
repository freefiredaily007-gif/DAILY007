Build a complete and production-ready UPI payment system for my coin-based gaming application.

GOAL:
Users should be able to purchase coins by paying through UPI apps such as Google Pay, PhonePe and other supported UPI apps. After a successful payment, the purchased coins must automatically be verified and credited to the user's in-app Wallet without admin manually checking every payment.

IMPORTANT:
Do NOT create a fake payment-success system or simply credit coins when the user clicks "Pay". Coin credit must happen ONLY after the payment gateway/backend confirms the transaction as genuinely successful.

PAYMENT FLOW:

1. User opens Wallet → Buy Coins.
2. Show coin packages, for example:
   - ₹10 = 100 Coins
   - ₹50 = 500 Coins
   - ₹100 = 1000 Coins
   - ₹200 = 2000 Coins
     Admin should be able to edit packages.
3. User selects a package and clicks "Add Coins".
4. Create a unique payment/order ID on the backend.
5. Open a secure UPI payment checkout that supports Google Pay, PhonePe and other supported UPI apps.
6. User completes the payment.
7. Payment gateway sends the payment result to the backend through a secure server-side webhook/API.
8. Backend verifies:
   - payment/order ID
   - transaction ID
   - amount
   - currency
   - payment status
   - user/account ID
   - gateway signature/webhook authenticity
9. ONLY after successful server-side verification:
   - mark payment as SUCCESS
   - credit the exact purchased coins to the user's wallet
   - create a wallet transaction record
   - show "Coins Added Successfully"
10. Prevent duplicate coin credit if the same webhook/payment notification is received multiple times. Use idempotency/payment ID protection.
11. If payment fails, is cancelled, expires, or remains pending, DO NOT credit coins.
12. If payment is pending, show "Payment verification pending" and automatically update the status when the gateway confirms it.

WALLET:
Show:

- Current coin balance
- Total purchased coins
- Total used coins
- Transaction history
- Payment amount
- Coins received
- Date/time
- Payment status
- Unique transaction/order ID

TRANSACTION HISTORY:
Each transaction must have:

- transactionId
- userId
- orderId
- amount
- coins
- paymentMethod
- paymentStatus
- gatewayTransactionId
- createdAt
- verifiedAt

ADMIN PANEL:
Create a professional payment management section where admin can see:

- Pending payments
- Successful payments
- Failed payments
- Refunded payments
- Total payment amount
- Total coins credited
- User details
- Order ID
- Gateway transaction ID
- Date/time

SECURITY:

- Never trust coin balance or payment success from the frontend.
- Never expose secret API keys in frontend code.
- Keep payment gateway secret keys only in secure server environment variables.
- Verify webhook signatures.
- Use server-side payment verification.
- Use database transactions when crediting coins.
- Prevent replay attacks and duplicate webhook processing.
- Keep an immutable wallet transaction ledger.
- Never allow users to manually edit their coin balance.

PAYMENT GATEWAY:
Use a legitimate Indian payment gateway that supports UPI and Google Pay/PhonePe-compatible UPI payments, such as Razorpay or another suitable gateway available for the application's business type.

Do not hard-code fake API keys. Create environment variables such as:
PAYMENT_KEY_ID
PAYMENT_KEY_SECRET
PAYMENT_WEBHOOK_SECRET

Create the complete frontend, backend API, database models, webhook endpoint, payment verification logic, wallet ledger and admin payment dashboard.

Also add proper loading, success, failed, cancelled and pending states.

Before implementation, clearly identify which payment gateway integration is being used and provide the exact environment variables required. Do not claim that automatic verification works until the backend webhook and server-side verification are actually implemented.
