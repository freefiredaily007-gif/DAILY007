Build a complete UPI payment system for my coin-based application.

IMPORTANT REQUIREMENT:
Coins must NOT be automatically credited based on the paid amount.

The payment should be automatically verified by the payment gateway/backend, but the ACTUAL COIN CREDIT must be manually approved and entered by the ADMIN.

PAYMENT FLOW:

1. User opens Wallet → Add Money / Buy Coins.
2. User selects or enters the payment amount.
3. Show UPI payment checkout supporting Google Pay, PhonePe and other supported UPI apps.
4. Create a unique Order ID for every payment.
5. User completes the payment.
6. Payment gateway sends the payment result to the backend through a secure webhook.
7. Backend verifies the payment server-side.
8. If payment is genuinely successful:
   - Mark payment as "Payment Verified"
   - DO NOT automatically add coins.
   - Create a "Coins Pending Admin Approval" record.
9. Admin opens the Payment/Coin Management section.
10. Admin can see:

- User name
- User ID
- Paid amount
- Order ID
- Gateway transaction ID
- Payment status
- Date/time
- Current wallet balance

11. Admin manually enters the number of coins to credit.
12. Admin clicks "Approve & Credit Coins".
13. Only then should the entered number of coins be added to the user's wallet.
14. Create a permanent wallet transaction record showing:

- Payment amount
- Coins manually credited
- Admin approval
- Transaction ID
- Date/time

15. If admin rejects the request, NO coins should be credited.

EXAMPLE:
User pays ₹100.
Payment is automatically verified as SUCCESS.
System shows:
"Payment Verified – Coins Pending Admin Approval"

Admin decides to credit 850 coins.
Admin enters:
Coins = 850

After clicking "Approve & Credit Coins":
User wallet balance increases by exactly 850 coins.

The system must NOT automatically calculate or credit 1000 coins just because the payment was ₹100.

ADMIN FEATURES:

Create a professional "Payment & Coin Management" page with:

- Pending Coin Credits
- Payment Verified
- Approved
- Rejected
- Payment Failed
- Payment Pending

For every verified payment, provide:
[Enter Coins] [Approve & Credit] [Reject]

Admin must be able to manually enter any valid coin amount before approval.

SECURITY:

- Never trust payment status from frontend.
- Never trust coin balance from frontend.
- Verify payments server-side.
- Verify webhook signatures.
- Never expose payment gateway secret keys in frontend.
- Prevent duplicate payment processing.
- Prevent duplicate coin credit for the same approved transaction.
- Maintain an immutable wallet transaction ledger.
- Store admin ID, timestamp and approval action for every coin credit.

PAYMENT GATEWAY:
Use a legitimate Indian payment gateway that supports UPI payments through apps such as Google Pay and PhonePe.

Do not use fake payment verification.
Do not accept uploaded payment screenshots as proof of payment.
Do not hard-code API keys.

Use secure environment variables such as:
PAYMENT_KEY_ID
PAYMENT_KEY_SECRET
PAYMENT_WEBHOOK_SECRET

WALLET:
Show:

- Current Coins
- Pending Coin Credits
- Total Coins Added
- Total Coins Used
- Transaction History

TRANSACTION HISTORY:
Each transaction should show:

- Transaction ID
- Order ID
- Payment amount
- Coins credited
- Payment status
- Admin approval status
- Date/time
- Admin approval timestamp

IMPORTANT:
Payment verification and coin credit are two separate steps.

Payment = automatically verified by gateway/backend.
Coins = manually entered and credited by admin only after approval.

Implement the complete frontend, backend, database models, secure webhook, payment verification, wallet ledger and admin interface.
