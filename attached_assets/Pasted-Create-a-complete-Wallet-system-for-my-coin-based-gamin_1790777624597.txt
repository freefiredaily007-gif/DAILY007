Create a complete Wallet system for my coin-based gaming tournament application.

1. ADD COINS SYSTEM

On the Wallet page, show:

- Current Coin Balance
- “ADD COINS” button
- “WITHDRAW” button
- Transaction History

When user clicks ADD COINS:

Open an Add Coins payment screen showing:

- Available coin packages configured by Admin
- Admin's UPI ID
- Admin's UPI QR Code
- Clear payment instructions

Example:
₹10 = 100 Coins
₹20 = 200 Coins
₹50 = 500 Coins
₹100 = 1000 Coins

The Admin must be able to change coin packages, UPI ID and QR code from Admin Panel.

After the user makes the UPI payment, show a form:

- Enter Transaction ID / UTR Number
- Enter Paid Amount
- Enter Coins Requested
- Optional payment screenshot upload
- Submit Payment Request button

After submission:

- Do NOT add coins immediately.
- Create a payment request with status PENDING.
- Change the Submit button to PAYMENT PENDING.
- Disable duplicate submission for the same request.
- Show request details and submitted time.
- User can see the request in Transaction History.

2. ADMIN ADD-COIN APPROVAL

Create an Admin Panel → Coin Payment Requests section.

Admin can see:

- Username/User ID
- UPI Transaction ID / UTR
- Paid Amount
- Requested Coins
- Screenshot if uploaded
- Date & Time
- Status

Admin buttons:

- APPROVE
- REJECT

When Admin clicks APPROVE:

- Add the approved coins to the user's wallet automatically.
- Create a wallet transaction record.
- Payment status becomes APPROVED.
- User's Add Coins button becomes normal again.
- Send an in-app notification: “Your coin payment has been approved.”

When Admin clicks REJECT:

- Do not add coins.
- Payment status becomes REJECTED.
- User can submit a new request.
- Send an in-app notification with rejected status.

3. WITHDRAW SYSTEM

When user clicks WITHDRAW:

Show:

- Current Coin Balance
- Minimum withdrawal coins configured by Admin
- UPI ID input
- Coins to withdraw input
- Expected payout amount
- Submit Withdrawal Request button

Before submission validate:

- UPI ID is required.
- Coins must be valid.
- User must have sufficient coin balance.
- Coins must meet Admin's minimum withdrawal requirement.

IMPORTANT:
Do NOT permanently deduct/complete the withdrawal until Admin approves it.

When submitted:

- Create a Withdrawal Request with status PENDING.
- Reserve/hold the requested coins so the user cannot use the same coins for another withdrawal or tournament entry.
- Change the withdrawal button/status to WITHDRAWAL PENDING.
- Prevent duplicate withdrawal requests while one is pending.

4. ADMIN WITHDRAWAL APPROVAL

Create Admin Panel → Withdrawal Requests.

Admin can see:

- Username/User ID
- UPI ID
- Requested Coins
- Payout Amount
- Date & Time
- Current Status

Admin buttons:

- APPROVE
- REJECT

When Admin APPROVES:

- Confirm the withdrawal.
- Deduct/settle the held coins permanently.
- Mark withdrawal as APPROVED/PAID.
- Create wallet transaction history.
- Notify the user: “Your withdrawal has been approved.”
- User cannot reuse those coins.

When Admin REJECTS:

- Mark request as REJECTED.
- Release the held coins back into user's available wallet balance.
- Notify the user.
- Allow the user to create a new withdrawal request.

5. WALLET TRANSACTION HISTORY

Create a proper transaction history with:

- Add Coins
- Tournament Entry
- Tournament Refund
- Withdrawal
- Admin Adjustment

Each transaction should show:

- Coins
- Type
- Status
- Transaction ID
- Date & Time
- Balance after transaction

Use statuses:
PENDING
APPROVED
REJECTED
PAID
REFUNDED

6. SECURITY & DATA CONSISTENCY

Implement this using backend/database transactions so coins cannot be duplicated or lost.

IMPORTANT RULES:

- Never add coins just because the user submits a payment request.
- Only Admin approval can credit purchased coins.
- Never allow a user to approve their own payment or withdrawal.
- Prevent duplicate UTR/Transaction IDs from being submitted.
- Prevent duplicate coin credit for the same approved payment.
- Prevent withdrawal of more coins than available.
- Maintain a complete wallet ledger for every coin movement.
- All Admin actions must update the database immediately.
- User wallet balance must always match the transaction ledger.
