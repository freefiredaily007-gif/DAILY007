Referral & Reward Coin System

Implement a complete and secure Referral & Reward Coin System in the FreeFire Daily007 application.

1. Referral Code / Referral Link

- Every registered user must have a unique referral code.
- The user can share their referral code or referral link with friends.
- A new user can enter the referral code during signup.
- The referral relationship must be permanently linked to the new user's account.

2. New User Signup Reward

When a new user signs up using a valid referral code:

- The new user receives 10 bonus coins in their wallet.
- The 10 coins should be credited automatically after successful signup.
- The referral reward transaction must be recorded in the wallet/transaction history.
- A user cannot receive the signup referral bonus more than once.
- A user cannot refer themselves.

3. Referrer's Reward

The person who referred the new user should NOT receive the 5-coin reward immediately after signup.

Instead, the referrer receives 5 bonus coins only after the referred user completes their first successful recharge of at least 50 coins.

Example:

- User A refers User B.
- User B signs up using User A's referral code.
- User B receives 10 bonus coins.
- User B later recharges 50 coins or more.
- After that recharge is successfully approved/confirmed, User A automatically receives 5 bonus coins.

4. Minimum Recharge Requirement

The referral reward is triggered only when:

- The referred user makes their first successful recharge.
- The recharge amount is 50 coins or more.

Examples:

- First recharge = 20 coins → Referrer gets 0 coins.
- First recharge = 49 coins → Referrer gets 0 coins.
- First recharge = 50 coins → Referrer gets 5 coins.
- First recharge = 100 coins → Referrer gets 5 coins.
- First recharge = 500 coins → Referrer gets 5 coins only.

The referrer must receive the 5-coin reward only once per referred user, regardless of how many times that referred user recharges later.

5. Recharge Approval Logic

If the application uses manual recharge verification:

- The referred user's recharge must first be approved/confirmed by the admin.
- The 5-coin referral reward should be triggered only after the recharge becomes successful/approved.
- Pending, rejected, cancelled, or failed recharges must NOT trigger the referral reward.

6. Wallet Transaction Records

Every referral-related coin transaction must be recorded properly.

For the new user:

- "Referral Signup Bonus"
- "+10 Coins"

For the referrer:

- "Referral Recharge Bonus"
- "+5 Coins"
- Include the referred user's ID/name and the qualifying recharge transaction ID.

7. Anti-Abuse & Security

Implement proper protection against referral abuse:

- One account can have only one referrer.
- Self-referrals are prohibited.
- The same referred user can generate the referrer's 5-coin reward only once.
- Do not give the 5-coin reward for rejected, cancelled, fake, or reversed transactions.
- Do not trigger the reward twice if the admin approves the same recharge more than once.
- Use a unique referral-reward transaction/reference ID to prevent duplicate rewards.
- Referral rewards must be handled through secure backend/database logic, not only frontend code.

8. Referral Dashboard

Add a My Referrals section where the user can see:

- Referral code
- Referral link
- Total people referred
- Successful referrals
- Pending referrals
- Total referral coins earned

For each referred user, show:

- User name/ID
- Signup status
- Signup bonus status
- First recharge status
- Whether the 5-coin referrer reward has been credited

Complete Example

User A
→ Shares referral link with User B.

User B
→ Signs up using User A's referral code.
→ Automatically receives 10 coins.

User B
→ Recharges 30 coins.
→ Referrer receives 0 coins because the minimum is 50.

User B
→ Later makes a successful first recharge of 50 coins or more.
→ User A automatically receives 5 coins.

After this:
→ User A cannot receive another 5-coin referral reward from User B's future recharges.

Build this as a complete frontend + backend + database system and make sure the wallet balance, transaction history, referral status, and admin approval system remain synchronized.
