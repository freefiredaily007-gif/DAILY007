7. REJECT RECHARGE

If Admin rejects:

Status:

REJECTED

Do not add any coins.

Admin can enter rejection reason.

Example:

“Invalid transaction ID”

User can see the rejection reason in Recharge History.

---

8. DUPLICATE PROTECTION

Transaction ID / UTR must be unique.

If the same transaction ID is submitted again:

Show:

“This transaction ID has already been used.”

Do not credit coins twice.

Admin also must not be able to approve the same recharge request twice.

Use backend/database atomic transactions.

10. WITHDRAW VALIDATION

Before submitting withdrawal:

Check:

- User is logged in
- Coin amount is valid
- User has sufficient available coins
- Minimum withdrawal amount configured by Admin is satisfied
- No duplicate pending withdrawal exists if such restriction is enabled

If insufficient coins:

“Insufficient coins.”

Do not allow withdrawal.

---

11. WITHDRAWAL REQUEST

When user submits a valid withdrawal:

Create a withdrawal request with:

- User ID
- User name
- Coin amount
- UPI ID
- Request date/time
- Status
- Admin review information

Status:

PENDING

Important:

The withdrawal amount must be securely reserved/deducted from the user's available balance when the request is created, so the same coins cannot be withdrawn or spent twice.

Show:

Withdrawal Pending

17. SECURITY

All wallet operations must be processed server-side.

Prevent:

- Negative balance
- Client-side balance manipulation
- Duplicate recharge approval
- Duplicate withdrawal
- Duplicate transaction ID
- Spending coins that are already reserved for withdrawal
- Withdrawing more coins than available
- Double crediting coins

Every wallet change must have an immutable transaction record and timestamp.

Use database transactions/atomic operations for:

- Recharge approval
- Withdrawal creation
- Withdrawal approval
- Withdrawal rejection/refund
- Coin deduction
- Coin credit

---

18. FINAL USER FLOW

ADD COINS:

Wallet → Add Coins → UPI ID + Copy → QR Scanner → Make Payment → Enter Coins + Transaction ID + Screenshot → Submit → Pending → Admin Approves → Coins Added.

WITHDRAW:

Wallet → Withdraw → Enter Coins + UPI ID → Submit → Coins Reserved → Pending → Admin Approves → Withdrawal Completed.

If rejected:

Withdrawal → Rejected → Coins Automatically Returned.

Make the entire Wallet, Add Coins and Withdraw system fully functional with frontend + backend + database + admin approval workflow.
