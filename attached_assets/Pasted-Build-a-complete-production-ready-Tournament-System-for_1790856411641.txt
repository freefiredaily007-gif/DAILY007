6. COIN WALLET INTEGRATION

Connect the tournament system to the application's wallet.

The application uses:

1 Coin = ₹1

Therefore:

10 Coins = ₹10
20 Coins = ₹20
50 Coins = ₹50
100 Coins = ₹100
500 Coins = ₹500

Tournament entry fees must be displayed as:

Entry Fee: 20 Coins (₹20)

Before registration, backend must verify:

- User is logged in.
- Tournament is active.
- Registration is open.
- Correct slot/team is available.
- User has sufficient coins.
- User has not already registered.

When registration succeeds:

1. Deduct the configured entry coins from the user's wallet.
2. Assign slot/team.
3. Create registration.
4. Create wallet transaction.
5. Update tournament count.
6. Confirm registration.

Everything must happen atomically.

Example:

Wallet:

"100 Coins (₹100)"

Tournament Entry:

"20 Coins (₹20)"

After joining:

"80 Coins (₹80)"

Create transaction:

Type: Tournament Entry
Coins: -20
INR Value: ₹20
Tournament ID: XXXXX
Date/Time: current timestamp

If registration fails, the user's coins must NOT be permanently deducted.

If a transaction fails after temporary deduction, automatically rollback.

- Unique constraints
- Atomic updates
- Server-side validation
- Idempotency where appropriate

Create unique constraints for:

"tournamentId + slotNumber"

"tournamentId + teamNumber"

"tournamentId + userId"

Prevent:

- Duplicate slot
- Duplicate team
- Duplicate registration
- Duplicate coin deduction

Return clear messages:

Already registered

Insufficient coins
